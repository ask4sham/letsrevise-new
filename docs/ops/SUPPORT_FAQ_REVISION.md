# Support FAQ — Revision (AI) generation — Phase 10.4

Internal reference for support and ops. No logic changes; explanation only.

---

## Why didn’t AI generate?

Revisions can be produced in two ways:

1. **AI-generated** — The slot engine called OpenAI and returned flashcards + quiz. The draft will have `engine.status === "COMPLETED"` and no `engine.errorCode` (or null).
2. **Heuristic (standard) fallback** — The engine did not run or did not return a valid result (e.g. gated by allowlist/rollout, or a failure). The draft will have `engine.status === "STUB"` and `engine.errorCode` set (e.g. `NOT_ALLOWLISTED`, `ROLLOUT_EXCLUDED`, `ENGINE_SPAWN_FAILED`, `OPENAI_*`).

So “AI didn’t generate” usually means the user got a revision that was produced by the **heuristic fallback**. The content is still valid; it just wasn’t generated by the model. Check `draft.engine.errorCode` to see why (allowlist, rollout, kill-switch, spawn failure, or OpenAI error).

---

## What does “revision unavailable” mean?

When the API returns **503** with `code: "REVISION_ENGINE_UNAVAILABLE"` or `"REVISION_GENERATION_DISABLED"`:

- The service is **not** returning a revision at all (no draft created).
- **REVISION_GENERATION_DISABLED** — Global kill-switch is on (`DISABLE_AI_REVISION_GENERATION=1`). No one gets AI revision; the route fails fast.
- **REVISION_ENGINE_UNAVAILABLE** — Used when `REVISION_NO_FALLBACK=1` (e.g. staging) and the engine returned STUB/failure, so the backend does not fall back to heuristic and instead returns 503. In production with fallback on, users would get heuristic content instead of 503.

Tell the user: “Revision is temporarily unavailable. Please try again later.” Do not say “AI is broken” — it may be a deliberate gate or a short-lived issue.

---

## How do I tell if AI is enabled?

- **For a single draft:** Check `draft.engine.status`. If `"COMPLETED"`, that draft was generated by the AI. If `"STUB"`, it was heuristic (or engine failed/gated).
- **For the system:** Use admin metrics: `GET /api/admin/revision-metrics`. If `completed > 0` and `byErrorCode` shows few ENGINE_SPAWN_FAILED / OPENAI_*, AI is running for at least some requests. If allowlist is enabled and rollout &gt; 0, and env (or config file) has `OPENAI_API_KEY` and `FEATURE_SLOTGEN_AI=true`, the system is configured for AI; actual usage depends on allowlist rules and rollout bucket.

---

## User-visible messaging (for frontend)

- **200 + draft with `engine.status === "STUB"`:** Show something like: “Revision generated using standard content. You can edit the draft before applying.” (API may include `messageForUser`.)
- **503 REVISION_ENGINE_UNAVAILABLE or REVISION_GENERATION_DISABLED:** Show: “Revision is temporarily unavailable. Please try again later.” (API includes `messageForUser`.)

Avoid technical terms (allowlist, rollout, errorCode) in the UI; use the above explanations.
